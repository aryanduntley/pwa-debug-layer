--------------------------------------------------------------------------------
0. CRITICAL PREREQUISITE — why a Claude Code restart alone is not enough
--------------------------------------------------------------------------------

.mcp.json launches the pwa-debug MCP server as `node packages/host/dist/main.js`
— the BUILT artifact, not TS source. Claude Code fetches the tool list once at
MCP-connect (session start) and never hot-reloads it. So the four react_* tools
only become callable after, IN THIS ORDER:

  1. Build:  pnpm -w build
     (shared+host+extension; regenerates dist/main.js with react_tree,
      react_get_state, react_find_by_text, react_find_by_role registered in
      packages/host/src/mcp/tools/index.ts)
     -- DONE at M22 close; redo if host/extension source changed since.

  2. Reload the unpacked extension at brave://extensions
     (rebuilt service-worker.js = request_router; page-world.js = page_dispatch
      — they carry the new react_find_by_* handlers). MANUAL browser step.

  3. Restart Claude Code
     (relaunches the fresh dist/main.js and re-fetches tools/list).

A Claude Code restart WITHOUT step 1 just relaunches the stale build. See
AIMFP note #124 (milestone 23).

Sanity check after restart: the tool list should now include
mcp__pwa-debug__react_tree, react_get_state, react_find_by_text,
react_find_by_role. If it does not, step 1 or 3 was skipped.

2. Smoke cases (run from Claude Code as MCP tool calls; user verifies)
--------------------------------------------------------------------------------

A. Baseline connection
   Tool: host_status   Args: {}
   Expect: ok. activeConnections has the extension; pageWorld.url == :5173.

B. react_tree default — tree shape
   Tool: react_tree    Args: {}
   Expect: ok. data.rootCount === 1. data.truncated === false (depth_limit 8,
           max_nodes 200 are ample for this fixture).
           data.roots[0].displayName === 'HostRoot'.
           Its descendant component nodes include App, then under App's
           wrapper <div> the components Counter, TodoList, UserProfile,
           NestedSection (DeepChild under NestedSection). Host fibers (div,
           section, h1, h2, p, ul, li, button, input, label) are interleaved
           and appear as nodes with displayName === their tag name — this is
           expected (react_tree emits every fiber).
           hasHooks true for Counter (useState) and TodoList (useReducer);
           UserProfile hasHooks/hasState both false (props-only).
   CAPTURE the stableId of Counter, TodoList, UserProfile from the response
   (e.g. root0/App[0]/.../Counter[0]). Do NOT hardcode — read them back.

C. react_tree depth_limit truncates
   Tool: react_tree    Args: { "depth_limit": 1 }
   Expect: ok. data.truncated === true; nodes below depth 1 pruned.

D. react_get_state on Counter — useState + props
   Tool: react_get_state   Args: { "stable_id": "<Counter id from B>" }
   Expect: ok. data.displayName === 'Counter'.
           data.props === { initial: 0, step: 1 }.
           data.hooks[0] === { type: 'state', index: 0, value: 0 }.
           data.state absent (function component, not class).
           data.truncated absent/false.

E. Subscription-free re-read after a render
   In the page, click Counter's "+" button:
     evaluate({ "expression":
       "Array.from(document.querySelectorAll('button')).find(b=>b.textContent.trim()==='+').click()" })
   wait ~50ms, then:
   Tool: react_get_state   Args: { "stable_id": "<same Counter id>" }
   Expect: ok. data.hooks[0].value === 1 (initial 0 + step 1). Proves M20
           stableId identity survives re-render and no page-world subscription
           leak. (Note: a bare document.querySelector('button') would hit
           Counter's "-" button first and give -1 — use the "+"-text filter.)

F. react_get_state on TodoList — useReducer state
   Tool: react_get_state   Args: { "stable_id": "<TodoList id from B>" }
   Expect: ok. data.hooks contains an entry of type 'state' whose value is the
           todos array [{id:1,text:'todo-marker-A',done:false},
           {id:2,text:'todo-marker-B',done:true}] (state/reducer conflated by
           design — see M21 T3 note). data.props === {} or empty.

G. react_get_state include_hooks:false
   Tool: react_get_state   Args: { "stable_id": "<Counter id>", "include_hooks": false }
   Expect: ok. data.hooks undefined. next_steps mentions include_hooks:false.

H. react_get_state stale id — tool-level error path
   Tool: react_get_state   Args: { "stable_id": "root0/Nope[0]" }
   Expect: ok:false. error matches /did not resolve/.
           next_steps mentions re-calling react.tree.

I. react_tree root_index out of range
   Tool: react_tree    Args: { "root_index": 99 }
   Expect: ok. data.rootCount === 1, data.roots === [].
           next_steps mentions "out of range".

J. react_find_by_text — partial (substring) match
   Tool: react_find_by_text   Args: { "pattern": "todo-marker-A" }
   Expect: ok. data.matches non-empty. Matches are HOST fibers whose trimmed
           textContent contains 'todo-marker-A' — because textContent is
           cumulative, expect MULTIPLE matches: the innermost element (label
           or li) AND every containing ancestor up to the app <div>
           (displayName = tag: 'li','label','section','div', etc.). Each match
           has { stableId, displayName, key?, matchedText:'todo-marker-A' }.
           data.truncated === false (well under default max_matches 20).
           This many-ancestor behavior is BY DESIGN (M22 matches any
           HostComponent; no smallest-enclosing logic — out of scope).
   Then: react_get_state({ stable_id: <one returned match id> }) -> ok;
         returns that host element's props (host-level, expected).

K. react_find_by_text — exact + max_matches + no-match + bad regex
   Args: { "pattern": "counter-marker: 0", "exact": true }
     -> ok. Matches only host nodes whose FULL trimmed text === 'counter-marker:
        0' (the <p>). Fewer than the partial case (ancestors include sibling
        text so their full text differs).
   Args: { "pattern": "todo-marker", "max_matches": 1 }
     -> ok. data.matches length 1, data.truncated === true.
   Args: { "pattern": "zzz-no-such-text" }
     -> ok. data.matches === []. next_steps gives no-match guidance.
   Args: { "pattern": "(" }
     -> ok:false. error matches /invalid regex pattern/. next_steps mentions
        the regex is new RegExp (no flags).

L. react_find_by_role — explicit role + accessible name
   Tool: react_find_by_role   Args: { "role": "region", "name": "user profile" }
   Expect: ok. data.matches has exactly the UserProfile <section>:
           { stableId, displayName:'section', role:'region',
             name:'user profile' }. (explicit role attr + aria-label name.)
   Then react_get_state on that stableId -> ok (host section props).

M. react_find_by_role — implicit roles + filters + errors
   Args: { "role": "heading" }
     -> ok. Matches the <h1> ("pwa-debug React fixture") and the <h2>s
        ("todos", "user-profile-marker", "nested-section") — implicit role
        from tag. displayName 'h1'/'h2'.
   Args: { "role": "button" }
     -> ok. Matches every <button> (Counter -, Counter +, each todo "x",
        TodoList "add"). Spot-check count vs the rendered page.
   Args: { "role": "region", "name": "no-such-name" }
     -> ok. data.matches === []. next_steps no-match guidance.
   Args: { "role": "button", "name": "(" }
     -> ok:false. error matches /invalid name regex/.
   Args: { "role": "button", "root_index": 99 }
     -> ok. matches [], rootCount 1, next_steps mentions out of range.

N. Resilience — stableId stable across an identity-preserving re-render
   Re-run E's "+" click once more, then react_tree({}) again.
   Expect: the Counter / TodoList / UserProfile stableIds captured in B
           resolve to the SAME components (ids unchanged by re-render).
           react_get_state on the old Counter id still works; hooks[0].value
           now 2.

O. Resilience — key-bearing identity survives sibling position change
   The fixture reducer has add/toggle/remove (no explicit reorder). Remove the
   first todo to shift the second's sibling position while its key stays:
     evaluate({ "expression":
       "(()=>{const li=Array.from(document.querySelectorAll('li')).find(l=>l.textContent.includes('todo-marker-A'));li&&li.querySelector('button').click();})()" })
   wait ~50ms.
   Expect: react_find_by_text({ pattern:'todo-marker-B' }) still finds it;
           react_tree shows one <li> remaining; a stableId for the
           todo-marker-B subtree continues to resolve via react_get_state
           (key={2} keeps identity though it moved from index 1 to 0).

--------------------------------------------------------------------------------
3. What "pass" means
--------------------------------------------------------------------------------

A–O return the expected ok/shape and next_steps. Non-failure deviations to
just document, not fail on:

- displayName 'Memo(X)'/'ForwardRef(X)' if a component is wrapped — correct.
- useReducer hooks reported as type:'state' (heuristic conflates state/reducer
  — M21 T3 note).
- findByText returning many ancestor matches for one marker — by design
  (cumulative textContent; no smallest-enclosing scoping in M22).
- findByRole host displayNames being tag names ('section','button','h2') not
  the React component name — correct (M22 matches HostComponent fibers).
- truncated:true only when a cap (depth_limit / max_nodes / max_matches) was
  actually hit.

--------------------------------------------------------------------------------
4. On failure — classify before patching
--------------------------------------------------------------------------------

1. No connection (host_status empty) -> reload extension at brave://extensions;
   verify NMH respawned; confirm Claude Code was restarted AFTER pnpm -w build.
2. Tool not found (react_find_by_* missing from the tool list) -> stale build
   or no Claude Code restart. Redo section 0 in order.
3. NMH error envelope ("... nmh error: page-bridge timeout") -> page-world not
   attached. Confirm the tab URL is http(s) (chrome://, brave://, web store
   can't run page-world). Inspect the SW console at brave://extensions for
   [pwa-debug] errors.
4. Tool-level error ("did not resolve") on a fresh tree -> fiber walk shape
   off; inspect __reactContainer$* on #root via evaluate; compare against
   computeStableId in packages/extension/src/react/compute_stable_id.ts.
5. findByText/findByRole wrong/empty when DOM clearly matches -> check
   packages/extension/src/react/find.ts (walkAndFilter HostComponent gate /
   implicitRoleForElement / computeAccessibleName) and find_by_text.ts /
   find_by_role.ts. Capture the host node's textContent / role / aria-label
   via evaluate and compare.
6. Wrong stableId format (missing root0 prefix, extra/missing segments) ->
   compute_stable_id.ts vs a manual fiber.return walk in evaluate().
