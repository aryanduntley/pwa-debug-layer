STEP 3 — M13 decomposition sketch (for when commit is done)
--------------------------------------------------------------------------------

M13 = "Shadow DOM + same-origin iframe + cross-navigation acceptance test".
This is the Path 2 EXIT criterion. Closing it ends Core Capture.

Tech shape:
- packages/extension/src/captures/walk_shadow.ts (new): observe document
  AND any open shadow root by chaining a MutationObserver onto each
  shadow's host element. Closed shadow roots stay out of scope (cannot
  be reached without page cooperation; document that fact in the file
  header).
- Each producer in packages/extension/src/captures/ extends to walk
  shadow roots. capture_dom_mutation.ts is the principal change.
- manifest.json: content_scripts.all_frames flips to true. Cross-origin
  iframes get the script too, but the page-world MAIN-world script in
  cross-origin frames cannot reach the parent's framework hooks — events
  from those frames get isCrossOrigin=true.
- Frame identity: CS side uses chrome.runtime.sender.frameId; page-world
  derives a stable frameKey via window.parent walk. Every CapturedEvent
  gains frameId (number from CS) + frameKey (string from page-world).
  ConsoleEntry/NetworkEntry already have frameUrl + frameKey — the new
  frameId becomes a third tag.

Acceptance (manual retest in Brave per M5 discipline):
- Multi-frame test page with example.com + a same-origin iframe + an
  open-shadow web component.
- Cross-navigation behavior is the headline: events from BEFORE a
  navigation must remain in the tail AFTER the nav (host buffer
  persistence — that's the Core Capture promise the whole path exists
  to prove).
- Test page can be a tiny local HTML served via `python -m http.server`
  or via a chainsale-style live target if it uses shadow components
  (web3modal has shadow roots — chainsale already exercises that path).

Candidate task split (proposed; refine when decomposing for real):
  T-A: shadow DOM walk helper (walk_shadow.ts) — pure FP, unit-testable
       without a browser. Either new AIMFP module captures_shadow or
       absorbed into the existing captures module.
  T-B: producer extensions — capture_dom_mutation tracks shadow roots.
       capture_console / capture_xhr / capture_fetch / capture_websocket
       already work regardless of frame, but the frameId/frameKey
       tagging path needs to reach them too.
  T-C: manifest + frame identity wiring — manifest.json all_frames=true,
       CS-side frameId capture, page-world frameKey derivation.
  T-D: integration tests (vitest with happy-dom shadow + same-origin
       iframe) for the new pure walker + the tagging seam.
  T-E: live-validation task (T24 analog) — multi-frame page + Brave
       retest + cross-navigation persistence check. Closes M13 → Path 2.
